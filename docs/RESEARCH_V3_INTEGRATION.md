## 适配时补修

1. 失败或取消的 intake 不再把空执行产物列表写回用户配置；可继续回答，并恢复之前选择的产物。
2. 访谈回复、回执恢复在途时锁住高级设置，避免迟到快照覆盖刚改的模型或范围。
3. 增加“重新整理这条回答”。只有明确点击才创建下一轮；最初每轮只调用一次模型，后续改为上述有预算的有限重试。
4. 附件证据在任务行锁内核对状态和执行 token，再检查唯一记录；旧执行器不能干扰新尝试。清理未发布文件时重新检查引用，提交结果不明则保留字节。
5. 表内“赞助”等行与整张表一起选取或省略，不再独立抽出失去表头、单位的数字行。用户文字附件不套用网页相关推荐过滤规则。
6. Python 对输入摘录显式记录片段哈希、未验证的父来源哈希与 UTF-16 父区间，不把拼接片段冒充原始正文或 Python 原文偏移。
7. PPT 页脚仅列本页相关引用，最多 32 条分两行，避开版本号；依据及全部来源保留在附录中。

## HTTP 正文、浏览器与 PDF 分流

2026-10-19 后续本地修复：采集镜像安装 `trafilatura==2.3.1` 及 11 个锁定依赖，`pip check` 通过。复用现有 `Crawl4AI==0.9.5`、`pypdf==5.9.0`，不接入外部采集 API、代理或验证码服务。

- 普通网页先用直连 HTTP 获取，再以 Trafilatura 提取带表格、链接的 Markdown；正文不足才使用浏览器渲染并再次提取。
- 研究阅读和核验不再强制截图；视觉留档阶段仍可请求截图。正文成功而截图失败时，正文保持成功并单独记录截图状态与原因，不能缓存命中正文就冒充已有截图。
- 根据最终 Content-Type、URL 和 PDF 文件头分流，PDF 最多 20 MiB、80 页、50 万字符；图片型 PDF 明确提示需要 OCR，不将它当成已读正文，也不交给浏览器。
- HTTP 重定向逐跳检查；连接器使用已检查的公开 DNS 结果，拒绝私网和不支持的文件类型，限制下载字节数。访问验证页面保留失败状态，不将其正文或截图当作研究材料。
- 方法、截图状态、警告及 PDF 页数与源文件哈希存入已有证据 metadata，不增加数据库迁移。
