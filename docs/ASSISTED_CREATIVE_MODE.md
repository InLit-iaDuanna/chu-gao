# 辅助创作模式：Agent 第二阶段

本地实现日期：2026-09-30。尚未部署生产服务器。

## 使用流程

入口在生图页输入框上方的“创作 Agent”，也可以打开 `/app?mode=agent`。

1. 像和助手聊天一样输入创作需求。消息会立即显示，Agent 返回自然语言理解、必要追问和结构化方案；服务端使用后台现有的对话模型，只整理需求，不创建生图任务。
2. 方案卡默认只显示结论。需要精细控制时打开“编辑方案”，再编辑画面目标、保持不变、本次修改、排除内容和视觉风格。字段可锁定；锁定后需先解锁才能手动编辑，模型重新整理也不能覆盖这些字段。
3. 在基图选择器中可以明确选择当前对话内的历史图片或已上传图片。用户说“上一张”“这张”“原图”等编辑意图时，会把上传参考图或上一张结果作为候选基图并写入方案；其他新建画面仍不会自动套用旧图。
4. 选定基图后，Agent 会调用受控的参考图分析工具，把可观察的主体、构图、风格和不确定项交给方案整理；分析失败时仍会退回纯文字流程，不会假装看过图片。
5. 点击“核对并生成”，查看模型、尺寸、基图、完整提示词和服务端报价。点击最终确认才创建一次生成任务，数量固定为一张。生成完成后仍停留在 Agent 页面，结果会自动设为下一轮基图，并调用质量检查工具对照当前方案给出通过、复核或失败结论。

未配置对话模型或整理失败时会明确报错，保留原需求；仍可手动填写方案。第一版没有把规则拼接伪装成模型分析。

## 实现范围

- 沿用现有 Next.js、PostgreSQL、BullMQ、Zod、对话模型和图片渠道，没有添加 Agent SDK 或外部服务。
- 规划请求会携带最近 12 轮 Agent 对话，后续追问会继续使用此前的约束和决定，不再只根据当前输入重新整理。
- `lib/creative-brief.ts` 定义共享校验、锁定合并和提示词拼装。模型不能设置渠道、费用、张数或触发工具。
- `/api/creative/plan` 只请求一次对话接口，无自动网络重试；模型输出必须通过 Zod 校验，锁定字段由服务端重新覆盖为原值。客户端也合并锁定字段。参考图观察报告作为不可信工具上下文传入，不能覆盖用户指令。
- `/api/creative/inspect` 校验用户对上传图和历史生成图的归属，只在服务端读取私有文件并压缩成有限大小的多模态预览；不会把私有 `/api/upload` URL 直接交给上游。
- `/api/creative/check` 校验生成结果和图片归属，按当前方案调用视觉模型输出结构化验收结果。它是 Agent 生成完成后的自动工具调用，不会自动扣生图积分，也不会自动重绘。
- `/api/creative/quote` 重新校验模型和基图归属、文件可用性，按现有后台价格规则报价，不扣生图积分。
- `/api/generations` 在服务端根据确认方案构造提示词及唯一基图，固定单张，拒绝高于确认金额的价格。后续结算同样不能超过已接受金额。
- 新模式跳过旧的多轮提示词编译步骤，避免确认后的锁定项再次被模型改写。
- 草稿按当前浏览器会话、用户和对话隔离保存在 sessionStorage。已确认方案、锁定项、基图和操作编号随任务写入 `Generation.paramsRaw`。本轮没有数据库迁移，不改历史记录。

## 提交与执行保护

同一确认使用稳定的 UUID。服务端在创建任务的用户级数据库事务锁内，根据 `paramsRaw._submission.id` 查找旧任务并核对请求摘要；重放只返回原任务，不再扣款或入队。相同操作编号、不同内容返回冲突。API 也在价格、余额等易变检查之前尝试返回已存在的任务。

这是一条受控创建路径上的应用层幂等保护，**没有新增数据库唯一索引，也不宣称外部调用 exactly-once**。未来跨服务或新增任务创建路径必须继续使用同一保护或迁移为数据库唯一约束。

新模式任务带有 `single-submit` 执行策略：

- 三类生图适配器不自动重发生成 POST；获取已提交任务的状态仍可以重试。
- 账号池不在一次提交失败后自动切换账号重新生成。
- 配置模板不能覆盖本次已确认的提示词或增加张数。
- 进入过 RUNNING 又失去心跳的辅助任务不会自动重发，标记失败并提示上游结果未知，由现有账本退款路径处理。
- 尚未执行的 PENDING 辅助任务恢复时重新校验来源图片，保留原基图；缺图或参考快照不一致则终止，不悄悄退化成纯文字生图。
- Worker 在提交上游前检查执行令牌更新是否成功。返回多张时只保存本次确认的一张。

原有普通生图的重试策略没有整体迁移，先前审查报告中关于普通模式的风险仍需继续处理。

## 开关

`CREATIVE_ASSISTANT_ENABLED=false` 或 `0` 会隐藏前台入口并禁用方案整理、报价和新的辅助生成请求。默认启用。现有已提交任务仍可通过原有进度接口查看并完成。

开关由服务器读取；调整环境变量后需重启应用。尚未添加后台开关表单。

## 尚未包含

- 图上涂画、局部标注、真实 mask 编辑。
- 跨浏览器同步未提交草稿、独立的创作简报版本表及父子图片版本树。
- 局部涂画、精确 mask 编辑和标注坐标仍未实现；当前参考图工具是全图观察，不会替用户修改像素。
- Agent 仍需要用户确认报价后创建任务，工具调用边界是参考图分析、生成结果验收和结果回写；不会自主消耗生图积分，也不会自动重绘。
- 视觉检查依赖后台配置的多模态对话模型；如果上游是纯文本模型，页面会显示检查不可用，但不阻断结果使用。
- 参考图观察和质量检查结果目前保存在当前页面状态/会话草稿，不新增数据库表，也不改变既有生成记录。
- 上游请求编号持久化对账、完整 UNKNOWN 状态模型、全项目统一幂等约束。

## 验证

- 结构化方案、服务端锁定、报价与权限、预算上限、操作重放、网络失败后沿用确认、单次提交适配器、恢复基图和费用上限均有模拟测试。
- Playwright 在 1440×960、390×844、320×740 检查方案区与确认窗口；两个移动视口未发现横向溢出。
- 本地实际调用报价接口并检查确认窗口，没有点击真实付费生成，没有启动 Worker，也未实际调用规划模型。
- 验证截图在忽略目录 `output/playwright/creative-*.png`。
